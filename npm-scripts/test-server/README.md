# Тестовый JSON Server

Простой тестовый сервер на базе json-server для разработки фронтенда без бэкенда. Запускается локально и эмулирует API для тестирования форм и запросов.

## Запуск

```bash
npm run json-server
```

Сервер запустится на порту **3010**. Если порт занят, останови процесс, который его использует, или измени порт в `app/plugins/json-server.ts`.

## Что умеет

### GET запросы

Сервер возвращает данные из `db.json:` ключи в JSON-файле соответствуют сегментам пути в URL. Напримре `/posts/` вернет данные из `db.json` по ключу `posts`.

### POST запросы (multipart/form-data)

Сервер умеет парсить формы с типом `multipart/form-data` и возвращает JSON с данными формы:

```json
{
  "success": true,
  "message": "ок",
  "data": {
    "field1": "value1",
    "field2": "value2"
  }
}
```

Статус ответа: **208** (Already Reported). Если нужно изменить на успешный 200 или ошибку, меняй в коде.

### JSON Server API

Стандартные эндпоинты json-server работают из файла `db.json`:

- `GET /posts` - список постов
- `GET /posts/1` - конкретный пост
- `GET /comments` - список комментариев
- `GET /profile` - профиль
- `GET /form` - данные формы

Можно делать `POST, PUT, PATCH, DELETE` запросы — json-server обработает их и сохранит изменения в `db.json` (кроме эндпоинтов, перечисленных в `excludePath`).

**Важно**: Для исключения эндпоинтов из автоматической обработки `json-server` используется константа `excludePath`. Сейчас в ней указан `form`, чтобы POST-запросы к `/form` не перезаписывали тестовые данные в `db.json`, а обрабатывались нашей кастомной логикой.

## Работа с формами и тестирование их ответов

В `db.json` есть объект `form`, в котором находятся различные тестовые сценарии (варианты ответов). Чтобы получить нужный для теста ответ, необходимо передать GET-параметр `test` с названием варианта.

Пример:

* `/form/?test=success` — вернёт успешный ответ.
* `/form/?test=error` — вернёт ответ с кодом 200, но неуспешный по своей логике (например, с ошибкой валидации).

Все доступные варианты ответов уточняйте у разработчиков бэкенда и тестируйте их локально.

## Структура данных

Данные хранятся в `app/test-server/db.json`. Можешь менять его как хочешь - сервер автоматически перехапуститься с обновленными данными

## Настройка

Если нужно изменить порт, открой `app/plugins/json-server.ts` и поменяй `3010` на нужный порт в методе `server.listen()`.

Если нужно изменить логику обработки POST запросов или добавить новые эндпоинты - редактируй `app/plugins/json-server.ts`. Там всё довольно просто и понятно.

## Проблемы

**Порт занят?** Найди процесс: `netstat -ano | findstr :3010` и убей его: `taskkill /PID <номер> /F`

**Не работает POST?** Проверь, что отправляешь `Content-Type: multipart/form-data` с правильным boundary.
